# Как запустить и понять проект

## Запуск

Распакуй ZIP целиком. Дважды нажми START_WINDOWS.bat. В открывшемся браузере нажми Load demo investigation. Установка библиотек не нужна. Консоль должна оставаться открытой.

Если запуск через BAT не работает: открой app.py в VS Code, выбери установленный Python и запусти Run Python File in Terminal. Файлы detector.py, sample.csv и папка web должны остаться рядом с app.py.

## Что ты увидишь

12 событий, 9 ошибок входа, 3 IP и 4 предупреждения. Нажатие на предупреждение показывает время, аккаунты, исходные строки CSV и возможные действия аналитика. Это учебные данные, а не обнаруженная атака на твой компьютер.

## Как устроен код

1. **parse_csv в detector.py.** DictReader превращает CSV в словари. Проверяются столбцы, даты, IP и статусы. strptime превращает дату из текста в объект datetime. sorted упорядочивает события.
2. **analyze.** defaultdict(deque) создаёт отдельную очередь событий для каждого IP и каждой пары (IP, пользователь). Очередь позволяет быстро убрать старые события слева.
3. **Окно времени.** Перед обработкой события удаляем ошибки старше заданного числа минут. Ошибка ровно пять минут назад остаётся; пять минут и одна секунда — исключается.
4. **Порог.** Длина очереди показывает число ошибок. Множество имён показывает число разных пользователей. Эти значения сравниваются с порогом.
5. **Успешный вход.** Считаем ошибки только того же пользователя и IP. Если их достаточно, формируем предупреждение. Затем очищаем эту последовательность ошибок.
6. **emit.** Создаёт словарь предупреждения, копирует подтверждающие события и добавляет рекомендацию. Это объясняет, почему правило сработало.
7. **app.py.** Запускает локальный веб-сервер. Браузер отправляет CSV на /analyze; сервер вызывает analyze и возвращает JSON. Сервер доступен только на твоём компьютере.
8. **web/app.js.** Показывает результат, фильтрует таблицу, создаёт файлы отчётов. textContent безопасно отображает введённые строки как текст.

## Как проверить понимание через изменения

- В копии sample.csv измени 10:04 на 10:06: первый BURST исчезнет, а в 10:05 ещё не будет трёх предыдущих ошибок. Проверь результат.
- Поставь порог 4: группы из трёх ошибок перестанут вызывать предупреждения.
- Измени успешному входу admin IP на другой: правило SUCCESS_AFTER_FAILURES для него не сработает.
- Напиши неизвестный статус: приложение должно отклонить файл с номером строки.
- Переставь строки с разным временем: результат должен сохраниться, потому что программа сортирует события.

## Что можно объяснить на собеседовании

«Я анализирую журнал, а не атакую систему. Для каждого IP хранится история ошибок за окно времени. Отдельная история по IP и пользователю позволяет связать ошибки с последующим успешным входом. У каждого предупреждения есть подтверждающие строки. Порог настраивается, а ложные срабатывания требуют расследования».

Не называй несколько ошибок доказанным взломом. Один IP может принадлежать офисному роутеру, а успешный вход может означать, что человек вспомнил пароль. Важны проверка контекста и дополнительные журналы.
